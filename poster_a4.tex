\section{Abstract}
\justifying
Traditional Knowledge Management (KM) systems are typically designed for enterprise-scale cloud deployments and are often unsuitable for privacy-sensitive small networks. This project addresses that gap by building an edge-hosted, low-cost, and secure agentic Retrieval-Augmented Generation (RAG) platform on Raspberry Pi 5. 

The design emphasizes offline-first operation, local storage, and encrypted remote access so that personal and institutional documents can be queried without sending data to third-party cloud services.

The core problem observed in earlier iterations was poor retrieval quality on OCR-heavy documents: fixed-length chunking broke semantic continuity, while single-stage dense retrieval frequently missed exact lexical matches. To solve this, the system integrates context-aware metadata chunking, hybrid dense+sparse retrieval, and post-retrieval refinement.

The objective is to provide reliable question answering over personal and institutional document collections while preserving data sovereignty. The upgraded pipeline improves factual grounding and retrieval relevance, with RAGAS evaluation showing 94.1\% Faithfulness and 100\% Context Recall on SQuAD.

	extbf{Key Contributions:}
\begin{itemize}
    \item Edge deployment with private networking and local NVMe storage.
    \item Context-aware chunking that preserves document structure and metadata.
    \item Hybrid dense+sparse retrieval with rank fusion and cross-encoder reranking.
    \item Agentic orchestration (ReAct-style) for tool-assisted, grounded responses.
\end{itemize}

\section{Methodology}
The pipeline is organized into modular stages to improve retrieval robustness on both clean text and OCR-fragmented content while keeping compute and storage feasible on edge hardware.

	extbf{Implementation Notes:} Documents are normalized during ingestion (OCR cleanup + metadata extraction), embedded into a vector store for semantic search, and indexed for lexical retrieval. Retrieved passages are fused, reranked, and then passed to the LLM with citations to reduce hallucinations and improve traceability.

	extbf{Processing Steps:}
\begin{itemize}
    \item Ingest documents (network share / upload) and extract OCR text + metadata.
    \item Chunk with structure-aware boundaries and enrich chunks with metadata fields.
    \item Build semantic (vector) and lexical (BM25) indices for retrieval.
    \item Retrieve, fuse, rerank, and diversify context before answer generation.
\end{itemize}

	extbf{System Stack:} Paperless-ngx manages ingestion and OCR; extracted text and metadata are stored with PostgreSQL. Hybrid retrieval uses ChromaDB (vector index) plus BM25 (lexical index). The Q\&A service is exposed via FastAPI, and the local client UI is built using PySide6.

	extbf{Retrieval \& Ranking Details:} Dense search uses MRL embeddings optimized for CPU efficiency, while BM25 captures exact lexical overlap. The two lists are merged via Reciprocal Rank Fusion (RRF) with \mbox{k=60}, then cross-encoder reranking and MMR reduce noise and redundancy.

	extbf{1) Edge Infrastructure and Ingestion}
\begin{itemize}
    \item Hardware: Raspberry Pi 5 (8GB RAM) with 512GB NVMe SSD and active cooling.
    \item Secure access through Tailscale (WireGuard-based mesh networking).
    \item Document flow: upload/Samba share $\rightarrow$ OCR extraction $\rightarrow$ metadata processing.
    \item Goal: enable private, low-latency search and Q\&A within small-scale networks.
\end{itemize}

	extbf{2) Context-Aware Metadata Chunking}
\begin{itemize}
    \item Replaces rigid 1000-character chunking.
    \item Preserves semantic/structural boundaries.
    \item Injects metadata (title/date/section) into each chunk.
    \item Reduces context loss across headers, tables, and multi-page sections.
\end{itemize}

	extbf{3) Hybrid Retrieval Pipeline}
\begin{itemize}
    \item Dense semantic retrieval via MRL embeddings.
    \item Sparse lexical retrieval using BM25.
    \item Rank fusion via Reciprocal Rank Fusion (RRF).
    \item Hybrid search improves exact-match queries and semantic paraphrases.
\end{itemize}

	extbf{4) Precision \& Diversity Orchestration}
\begin{itemize}
    \item Cross-encoder reranking for query-document interaction quality.
    \item MMR to reduce redundancy and improve context diversity.
    \item Encourages coverage of multiple relevant passages in the final context.
\end{itemize}

	extbf{5) ReAct Agentic Framework}
\begin{itemize}
    \item Multi-step reasoning with tool use.
    \item Uses web search and calculator for grounded responses.
    \item Final answer generation via Groq-backed LLM inference.
    \item Tool calls are used only when needed to reduce cost and latency.
\end{itemize}

\section{Results and Discussion}
	extbf{Evaluation Framework:} RAGAS\\
	extbf{Datasets and Protocol:}
\begin{itemize}
    \item SQuAD (100 questions)
    \item Proprietary synthetic OCR-heavy dataset (20 questions)
    \item Metrics computed on Faithfulness, Relevancy, Precision, and Recall
\end{itemize}
	extbf{Metrics (RAGAS):}
\begin{itemize}
    \item Faithfulness: answer consistency with the retrieved context.
    \item Answer Relevancy: how well the response matches the user query.
    \item Context Precision: proportion of retrieved context that is relevant.
    \item Context Recall: coverage of all relevant context needed to answer.
\end{itemize}

Overall, the hybrid retrieval + reranking stack improves grounding and coverage compared to single-stage retrieval, with the largest gains observed on structured benchmark questions.

The OCR-heavy dataset shows a drop in relevancy and context metrics due to fragmented tokens and noisy line breaks, supporting metadata-aware chunking and hybrid retrieval for scanned documents.

	extbf{Key Findings}
\begin{itemize}
    \item Hybrid retrieval achieved perfect recall on structured benchmark data.
    \item Cross-encoder reranking and MMR improved contextual quality and reduced noise.
    \item Real-world OCR-fragmented documents remain more challenging than clean corpora.
    \item Even on noisy inputs, the pipeline sustains usable faithfulness and relevance.
    \item Metadata-aware chunking reduced fragmentation errors near section boundaries.
\end{itemize}

\section{Conclusion}
The project demonstrates that an enterprise-style knowledge workflow can be adapted to low-power edge infrastructure without compromising privacy. The integration of context-aware chunking, hybrid retrieval, reranking, and agentic tool use substantially improves answer quality compared to a baseline dense-only pipeline.

In practice, the approach is most effective when metadata is consistently captured during ingestion and OCR output is normalized, enabling stable retrieval even across heterogeneous document formats.

	extbf{Achievements}
\begin{itemize}
    \item Reliable edge deployment with secure remote access and local data control.
    \item Strong benchmark outcomes with high faithfulness and perfect SQuAD recall.
    \item Practical multi-tool reasoning support through ReAct-style orchestration.
\end{itemize}

	extbf{Future Scope}
\begin{itemize}
    \item Replace OCR-heavy stages with lightweight Vision-Language Models.
    \item Add persistent agentic memory for long-horizon conversations.
    \item Extend deployment to academic labs, departmental archives, and small offices.
\end{itemize}
